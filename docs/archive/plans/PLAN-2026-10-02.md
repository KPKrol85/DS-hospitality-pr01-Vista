# Vista — Development Plan

**Last reviewed:** 2026-10-02

**Project:** Demonstrational static multi-page hospitality website; HTML, modular CSS, vanilla JavaScript, Node.js tooling and Netlify configuration

**Source:** Final Technical Front-End Audit dated 2026-09-30 ([archived audit](../audits/AUDIT-2026-10-02.md))

**Recorded verification:** 2026-10-01 (`PH1-01`–`PH2-05`) and 2026-10-02 (`PH3-01`)

**Status:** COMPLETED — eight source corrections and one integration-verification objective verified; this plan is archived.

## Scope

Vista presents a fictional hospitality brand; its contact form sends a project inquiry and does not reserve accommodation or process payments. The plan corrected the audit's three P1 and five P2 findings without adding product capabilities or changing the architecture, then verified the combined result in a fresh production package. No optional or deferred work was in scope.

The source/production build separation, reveal fallback, native-validation baseline, arrival-date gate and demonstrational content attribution were preservation constraints, not new tasks. The `PH1-01` breakpoint defect was distinct from the closed-mobile-menu correction in [the 2026-09-24 plan](PLAN-2026-09-24.md). Planning used static inspection and one read-only Sharp metadata check (381 image URL/width-descriptor pairs, 76 mismatches); no build, browser suite, deployment or live form delivery was verified during planning.

## Phase 1 — Important interaction and recovery corrections

- [x] **PH1-01 — Reset mobile navigation across the desktop breakpoint** — Entering desktop layout clears mobile open, body, toggle and focus-return state, and mobile closing and focus trapping are restricted to the mobile layout; `npm run qa:fast` and the new `nav breakpoint transition` scenario passed, with local source Chromium covering 390 → 960 → 961 → 1280 → 390 px, both desktop Tab boundaries, Escape, link selection, mobile focus return and no-JavaScript navigation (audit `P1-01`).
- [x] **PH1-02 — Resolve custom 404 assets and recovery links from any missing path** — `404.html` resolves styles, scripts, images, metadata payloads and recovery links from the domain root, with matching `scripts/build-dist.mjs` rewriting and assertions; `qa:fast`, the `missing-path recovery` scenario, syntax checks and `git diff --check` passed, local Chromium interception served it with HTTP 404 and the source CSP at shallow, nested and trailing-slash missing URLs with JavaScript enabled and disabled, and an in-memory build check verified 12 HTML rewrites, unchanged output for the other 11 pages and rejection of 17 malformed cases (audit `P1-02`).
- [x] **PH1-03 — Apply readable error text to every form surface** — Non-fieldset errors use theme-aware semantic styling while date-fieldset errors and validation associations are retained; rendered-pixel assertions at 1280 × 720 px measured all seven errors at a minimum of 5.855:1 in light and 6.432:1 in dark states across explicit and Auto themes (required 4.5:1), and focus, live-region, association and blocked-submission assertions passed; the four `validation errors visible` variants disable only axe `color-contrast`, which misresolves transparent and gradient dark surfaces (audit `P1-03`).

## Phase 2 — Validation, readability and metadata consistency

- [x] **PH2-01 — Validate the complete guest-count value** — Enhanced and native validation accept only integer guest counts 1–6; the focused regression for invalid, fractional and out-of-range values, error recovery, exact `booking` POST values and no-JavaScript constraints passed (audit `P2-01`).
- [x] **PH2-02 — Make the focused skip link readable** — The focused skip link reaches 7.26:1 text contrast in light and dark themes (required 4.5:1), and the keyboard regression confirmed visible focus and navigation to `#main` (audit `P2-02`).
- [x] **PH2-03 — Correct offer-badge contrast in dark mode** — Offer badges on `offers.html` and `index.html` reach 5.19:1 in light and 8.06:1 in dark states across explicit and Auto themes, with shared primary-button contrast unchanged; the dark-offer state was added to the accessibility scenarios (audit `P2-03`).
- [x] **PH2-04 — Match responsive-image descriptors to actual widths** — Descriptors were corrected for the six homepage gallery pictures (320–800w declared for 640–1600 px files), the Deluxe JPEG (1208w → 1280w) and the fourth gallery-room image (1600w → 1536w), and homepage gallery `<source>` elements received their `<img>` `sizes` after Chromium showed a `100vw` fallback; all 421 source descriptors match decoded metadata through the new `check:image-descriptors` check in `qa:fast`, and representative mobile/desktop DPR 1/2 selection matched rendered sizes (audit `P2-04`).
- [x] **PH2-05 — Align sitemap membership with the noindex policy** — `sitemap.xml` lists only the six intended indexable canonical pages; the cookies, privacy-policy and terms pages retain `noindex,follow` and public links, and local sitemap targets passed link-integrity checks (audit `P2-05`).

## Phase 3 — Verify the integrated production package

- [x] **PH3-01 — Verify corrected states in a fresh distribution** — `npm run qa:fast` and all 26 source accessibility scenarios passed, one fresh `npm run build` passed package verification for 12 HTML pages, and 21 isolated Chromium scenarios against `npm run preview` confirmed the corrected navigation, 404, form, contrast and image states; local preview only, without live Netlify behavior.

## Completion

- **Verified tasks:** 9/9 — eight source corrections (`PH1-01`–`PH1-03`, `PH2-01`–`PH2-05`) and the `PH3-01` production-package verification.
- **Outcome:** All eight audit findings were resolved and survived production bundling in the final local package check; no generated file was patched manually.
- **Limitations:** Verification used local Chromium only. `npm run preview` does not emulate the Netlify catch-all redirect, headers, Forms or Edge Functions, so 404 routing used interception and fixtures and valid inquiries were intercepted locally; live hosting, real inquiry delivery, offline behavior beyond precache installation, other browsers, assistive-technology announcements and WCAG conformance remain unverified. The `PH1-03` scenarios rely on rendered-pixel contrast assertions instead of axe `color-contrast`. An axe finding for the privacy-policy link in the explicit light theme, observed during `PH1-03`, was outside its scope and left unmodified.
