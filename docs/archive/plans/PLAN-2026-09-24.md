# Vista — Development Plan

**Project:** Demonstrational static multi-page site (HTML, CSS, Vanilla JavaScript)

**Source:** Final Technical Front-End Audit dated 2026-09-23 ([archived audit](../audits/AUDIT-2026-09-24.md))

**Recorded verification:** 2026-09-24 (`PH1-03`, `PH2-01`); no separate completion date was recorded.

**Status:** COMPLETED — all four objectives verified; this plan is archived.

## Scope

The plan resolved the audit's three P1 findings and one P2 finding without changing the source-to-`dist/` workflow. Root HTML, `css/`, `js/` and `assets/seo/` were the canonical sources; production bundles and `dist/` were generated. The Phase 1 objectives had no code dependency on one another; the owner's decision on public contact details gated `PH1-03`, and `PH2-01` depended on the final `PH1-02` form behavior.

## Phase 1 — Release-relevant corrections

- [x] **PH1-01 — Remove closed mobile navigation from keyboard order** — The closed JavaScript-controlled mobile menu is no longer rendered or focusable, including on initial load, while toggle, Escape, link-selection, focus-return, desktop and no-JavaScript navigation are preserved; local Chromium passed 390 px closed and open Tab/Shift+Tab traversal, toggle/Escape/link closing with focus return, 1280 px desktop navigation and the return to mobile width on source and a fresh `build:dist` package (11 pages) (audit `P1-01`).
- [x] **PH1-02 — Reject past arrival dates on inquiry submission** — Enhanced validation rejects past arrivals by the browser-local date, and a Netlify Edge Function rejects them by the Europe/Warsaw date, including no-JavaScript requests; local checks passed on source and fresh `dist/`, and the owner confirmed HTTP 422 for a deployed past-date POST and Netlify's success response for a valid inquiry (audit `P1-02`).
- [x] **PH1-03 — Make indexable hotel claims consistent with the fictional brand** — Vista remains a fictional brand, while the owner-confirmed real contact details are attributed to KP_Code Digital Studio; unsupported `Hotel`, location and customer-service claims were removed from JSON-LD, all six embedded/fetched pairs matched in source and a fresh package, and local Chrome 153 presentation checks passed (audit `P1-03`).

## Phase 2 — Documentation alignment

- [x] **PH2-01 — Correct bilingual README accessibility statements** — Both README languages describe the visible reveal fallback, enhancement-only animations, native constraints before enhanced initialization, the browser-local and Europe/Warsaw arrival-date rules and the inquiry/reservation distinction, and retain the WCAG disclaimer; focused source inspection and comparison with the `PH1-02` record confirmed Polish/English factual parity, with no tests, build or deployment run (audit `P2-01`).

## Completion

- **Verified tasks:** 4/4 (`PH1-01`–`PH1-03`, `PH2-01`).
- **Outcome:** All four audit findings were resolved. Phase 1 corrections were verified locally on source and fresh `build:dist` packages; `PH1-02` was additionally confirmed by the owner on the live deployment.
- **Limitations:** Static HTML has no moving arrival minimum, so no-JavaScript rejection relies on the Edge Function, whose Europe/Warsaw date can differ from the visitor's local date. Inspection of the valid inquiry in the Netlify Forms dashboard was not documented. Local checks do not establish live Google Maps rendering, Netlify Forms delivery or collection, or search-engine treatment. The `PH1-03` build reported an outdated Browserslist dataset; no dependencies were updated.
