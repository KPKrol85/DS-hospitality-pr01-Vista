# Vista — Focused Front-End Review

**Project:** Vista — static multi-page HTML, CSS, and Vanilla JavaScript site

**Review date:** 2026-09-20

**Review mode:** Focused static repository review

**Closure date:** Not recorded in the review; archived as `REVIEW-2026-09-23.md`.

**Status:** CLOSED — all seven recommendations implemented and verified as recorded in the completed 2026-09-23 plan.

## Scope and original assessment

The review inspected repository source statically for progressive enhancement, distribution packaging, dialog accessibility, license declarations, contact-form validation, service-worker caching and the contact map. It recorded five P1 and two P2 findings; no P0 risk was detected. No overall rating was recorded.

Final statuses below are based on [the completed 2026-09-23 plan](../plans/PLAN-2026-09-23.md). Where later audits independently observed the corrected behavior, that is stated separately.

## Findings and final statuses

### P0 — Critical risks

None detected.

### P1 — Important issues

#### [P1-01] Reveal styles hide primary content without JavaScript

- **Classification:** Defect — progressive enhancement, content visibility.
- **Original finding:** Every `[data-reveal]` element started at `opacity: 0` and only JavaScript revealed it, so the homepage hero and many sections stayed invisible without JavaScript.
- **Recommendation:** Make content visible by default and apply the hidden animation state only after JavaScript is active.
- **Final status:** Resolved — implemented and verified (`PH1-01`).
- **Resolution:** Reveal content is visible before JavaScript activates animations, including when initialization fails, while the enhanced transition is preserved.
- **Verification:** Representative homepage and subpage content was checked with JavaScript disabled and enabled; the final `PH2-01` integration compared reveal fallbacks in source and a fresh production package in local Headless Chromium 147. The 2026-09-23 audit independently observed visible no-JavaScript homepage reveal content.

#### [P1-02] Checked-in production bundles lag behind canonical sources

- **Classification:** Contract mismatch — distribution build, room filters, project disclosure.
- **Original finding:** Tracked JS and CSS bundles omitted room-filter, project-banner and filtered-card rules, and `build:dist` copied them unchanged, producing a package with inactive room filters and no project disclosure dialog.
- **Recommendation:** Regenerate the bundles from canonical sources and make distribution packaging reject or refresh stale bundles.
- **Final status:** Resolved — implemented and verified (`PH2-01`).
- **Resolution:** CSS and JavaScript bundles are generated directly in `dist/` from `css/style.css` and `js/script.js`, without tracked source-tree `.min` files, and both `build` and `build:dist` clean and rebuild the complete package.
- **Verification:** Fresh `build:dist` and `build` runs packaged 11 HTML pages with bundle verification, production-reference inspection, link integrity and syntax checks passing; local Chromium compared room filters, filtered-card hiding and project-notice persistence between source and production.

#### [P1-03] Modal focus can escape to the page behind it

- **Classification:** Source-visible risk — keyboard accessibility, project dialog, lightbox.
- **Original finding:** Both dialogs initially focused a `tabindex="-1"` container and wrapped Tab only from their first or last control, without making the page inert, so reverse tabbing could reach background controls.
- **Recommendation:** Contain focus from the initial container and prevent background controls from receiving focus while either dialog is open.
- **Final status:** Resolved — implemented and verified (`PH1-03`).
- **Resolution:** The project notice and gallery lightbox keep Tab and Shift+Tab inside the dialog from the initial container, block background focus while open and restore the previous focus target on close.
- **Verification:** Forward and reverse keyboard traversal was verified for both dialogs, and the final `PH2-01` integration compared project-notice and lightbox focus management between source and production in local Chromium.

#### [P1-04] Repository license metadata contradicts LICENSE

- **Classification:** Contract mismatch — licensing metadata, project documentation.
- **Original finding:** `LICENSE` declared Vista proprietary, while `package.json`, `package-lock.json` and both README language sections described it as MIT licensed.
- **Recommendation:** Align root package metadata and README license statements with `LICENSE`, preserving separate third-party dependency licenses.
- **Final status:** Resolved — implemented and verified (`PH2-02`).
- **Resolution:** `package.json` and the root `package-lock.json` entry were aligned with the proprietary `LICENSE`, the Polish and English README statements were confirmed, and third-party dependency licenses were preserved.
- **Verification:** The plan records a consistency check across `LICENSE`, package metadata and README without further method detail. The 2026-09-30 audit independently confirmed matching proprietary license metadata.

#### [P1-05] Contact form loses required-field validation without JavaScript

- **Classification:** Defect — contact form, progressive enhancement.
- **Original finding:** The form carried `novalidate` and required-field checks ran only in the JavaScript submit handler, so a visitor without JavaScript could submit an empty or malformed request.
- **Recommendation:** Preserve native constraint validation for the no-JavaScript path while retaining the enhanced error messages.
- **Final status:** Resolved — implemented and verified (`PH1-02`).
- **Resolution:** Native constraints for required fields, email, phone pattern, guest bounds and consent remain active without JavaScript; the enhanced handler disables native validation only after initialization and keeps the Netlify Forms route.
- **Verification:** Invalid no-JavaScript submissions were blocked by the browser, and the enhanced path handled valid and invalid inputs; the final `PH2-01` integration compared native and enhanced validation in source and production with the valid POST intercepted locally. The 2026-09-23 audit independently observed active native constraints with JavaScript disabled.

### P2 — Minor refinements

#### [P2-01] Image-only updates do not invalidate service-worker caches

- **Classification:** Source-visible risk — service worker, asset freshness.
- **Original finding:** The cache version hashed HTML and four static files but not images, and the worker served cached non-HTML requests first, so a same-URL image replacement could stay stale for returning visitors.
- **Recommendation:** Include published image changes in cache invalidation or use an update-aware strategy for mutable assets.
- **Final status:** Resolved — implemented and verified (optional item `O-01`).
- **Resolution:** A replaced image published at the same URL reaches returning visitors after an updated distribution is installed.
- **Verification:** A same-URL A → B production-package update was verified in persistent Chromium. The 2026-09-30 audit independently observed that the worker generator hashes packaged file contents, including images.

#### [P2-02] Map fallback becomes permanent after a slow or deferred load

- **Classification:** Source-visible risk — contact map.
- **Original finding:** A six-second timer marked the lazily loaded map as settled and the load handler ignored later successful loads, so the interactive map could stay hidden for the visit.
- **Recommendation:** Allow a late successful load to reveal the iframe and avoid expiring the map before a deferred load can start.
- **Final status:** Resolved — implemented and verified (optional item `O-02`).
- **Resolution:** A late successful iframe load reveals the interactive map, while failed or slow loads retain the fallback and external map link.
- **Verification:** Local Chromium with mocked iframe responses passed early and post-timeout loads, a synthetic error, a never-completing request and the no-JavaScript fallback, including link and iframe accessibility attributes.

## Limitations

- The original review was a static repository review and recorded no build or browser results.
- Closure verification was local. No live Netlify deployment, inquiry delivery or third-party map rendering was tested.
- The `P1-04` verification record does not describe the method of the consistency check beyond its completion.
