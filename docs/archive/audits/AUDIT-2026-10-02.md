# Vista — Final Technical Front-End Audit

**Audit date:** 2026-09-30

**Closure date:** 2026-10-02

**Project type:** Demonstrational static multi-page hospitality website (HTML, modular CSS, vanilla JavaScript), with Node.js tooling and Netlify configuration

**Audit mode:** Final repository and implementation review

**Readiness at original audit:** Needs important fixes

**Original rating:** 7/10

**Archive status:** CLOSED — all eight findings resolved through PH1/PH2 and verified in the final `PH3-01` production-package check within its recorded local scope.

## 1. Scope and assessment

The audit covered all 12 root HTML documents, all maintained CSS and browser JavaScript modules, build, development, preview, image, syntax, link, booking-date, JSON-LD and axe scripts, package metadata, Netlify configuration and Edge Function, service worker, manifest, robots, sitemap, README, project notes, license and selected image metadata. Archived audit and review findings were treated as historical context.

**Original assessment (2026-09-30):** Vista had coherent canonical-source ownership, a documented source/production split and useful executable checks; all 12 source routes loaded without page errors or failed local assets, and existing fast and accessibility checks passed. Recorded strengths included the source/production build contract, executable booking-date and JSON-LD checks, gallery and room-filter behavior, the native form baseline with Edge date rejection, visible reveal content, centralized dialog focus handling, Vista-scoped worker caching and JSON-LD without an operating `Hotel` entity. State-specific checks nevertheless confirmed three P1 and five P2 issues. No P0 risks or extra quality improvements were detected; production packaging and live Netlify behavior were not verified by the audit.

## 2. Closed findings

### P0 — Critical risks

None detected.

### P1 — Important issues

#### [P1-01] Open mobile navigation retains its keyboard trap after entering desktop layout

- **Status:** COMPLETED — verified.
- **Resolution:** Entering desktop layout clears mobile open, body, toggle and focus-return state while keeping navigation rendered; mobile closing and focus trapping apply only to the mobile layout (`PH1-01`).
- **Verification:** `npm run qa:fast` and a new breakpoint-transition scenario passed on source across 390 → 960 → 961 → 1280 → 390 px, covering Tab boundaries, Escape, focus return and no-JavaScript navigation. `PH3-01` repeated breakpoint recovery on the production preview.

#### [P1-02] The custom 404 document resolves assets and recovery links under the missing path

- **Status:** COMPLETED — verified.
- **Resolution:** `404.html` assets, JSON-LD payloads and recovery links resolve from the domain root, with matching production-build rewriting; HTTP 404 and noindex behavior are retained (`PH1-02`).
- **Verification:** Local Chromium interception served `404.html` with HTTP 404 at shallow, nested and trailing-slash missing paths, with JavaScript enabled and disabled; assets, navigation and skip links passed. `PH3-01` repeated the nested 404 fixture on the production preview.

#### [P1-03] Non-date form errors retain a dark red foreground in dark mode

- **Status:** COMPLETED — verified.
- **Resolution:** Errors outside the date fieldset use theme-aware semantic styling; date-fieldset styling and error associations are preserved (`PH1-03`).
- **Verification:** Rendered-pixel assertions for all seven errors in light, dark and both Auto states measured minimums of 5.855:1 light and 6.432:1 dark, with focus, `aria-invalid` and submission blocking checked. `PH3-01` reproduced these minimums on the production preview.

### P2 — Minor refinements

#### [P2-01] Enhanced guest validation accepts fractional and out-of-range values

- **Status:** COMPLETED — verified.
- **Resolution:** Enhanced and native validation accept only untruncated integer guest counts from 1 to 6 (`PH2-01`).
- **Verification:** A focused regression covered invalid and fractional values, error recovery, exact `booking` POST values and no-JavaScript constraints. `PH3-01` confirmed guest rejection and six locally intercepted exact-value submissions on the production preview.

#### [P2-02] The focused skip link has insufficient text contrast

- **Status:** COMPLETED — verified.
- **Resolution:** The shared skip link uses a sufficiently contrasting foreground/background pair while retaining its focused placement (`PH2-02`).
- **Verification:** A keyboard regression measured 7.26:1 in light and dark themes and confirmed navigation to `#main`. `PH3-01` measured 7.265:1 on the production preview.

#### [P2-03] Dark-theme offer badges keep white text on the mint primary color

- **Status:** COMPLETED — verified.
- **Resolution:** `.offer-card__badge` uses a theme-appropriate foreground/background pair without changing shared primary-button contrast (`PH2-03`).
- **Verification:** Badges on `offers.html` and `index.html` measured 5.19:1 light and 8.06:1 dark across explicit and Auto themes. `PH3-01` reproduced 5.190:1 and 8.061:1 on the production preview.

#### [P2-04] Several responsive-image width descriptors disagree with the actual image files

- **Status:** COMPLETED — verified.
- **Resolution:** Width descriptors in `index.html`, `rooms.html` and `gallery.html` match the decoded image widths, homepage gallery `<source>` elements received their `sizes`, and `check:image-descriptors` was added to `qa:fast` (`PH2-04`).
- **Verification:** All 421 source descriptors matched decoded metadata, and representative mobile/desktop DPR 1/2 checks selected consistent candidates. `PH3-01` confirmed 421 matching descriptors in `dist/` and the corrected packaged candidates.

#### [P2-05] The sitemap includes pages intentionally marked noindex

- **Status:** COMPLETED — verified.
- **Resolution:** The three legal pages were removed from `sitemap.xml` and retain `noindex,follow` and their public links (`PH2-05`).
- **Verification:** The sitemap lists the six intended indexable canonical pages and passed local link-integrity checks. `PH3-01` confirmed a byte-identical six-entry packaged sitemap.

## 4. Limitations

- **Original audit:** No live URL was supplied; live redirects, headers and CSP, Edge execution, Forms collection, third-party maps, external links and search-engine behavior were not verified. `dist/` was absent and no build was run. Only Chromium was used; Firefox, WebKit, physical devices, assistive technology, production performance and full contrast coverage were not tested. Automated dark-form contrast results affected by transparent layers were not accepted as findings. Legal compliance, asset rights and dependency vulnerabilities were not audited.
- **Closure:** Verification used local Chromium only. The preview does not emulate the Netlify catch-all redirect, headers, Forms or Edge Functions, so live hosting, real inquiry delivery, offline behavior beyond precache installation, other browsers, assistive technologies and WCAG conformance remain unverified. The four `PH1-03` scenarios disable axe `color-contrast` and rely on rendered-pixel assertions. An axe result for the privacy-policy link in the explicit light theme, observed during `PH1-03`, was outside its scope and left unmodified.

## 5. Final assessment

**Original readiness (2026-09-30):** Needs important fixes. The source site supported continued development and its existing checks passed, but the three P1 findings required resolution before final presentation or handoff, followed by verification of a fresh production package. The assessment did not establish deployment success, inquiry delivery, offline reliability or accessibility conformance.

**Original rating:** 7/10 — sound modular source, progressive-enhancement baseline, distribution ownership and regression checks, reduced by reproducible navigation and error-route defects, a validation-feedback contrast problem and narrower constraint and metadata inconsistencies missed by the existing test scenarios.

**Closure (2026-10-02):** All eight findings were resolved through PH1/PH2 and passed the final `PH3-01` local production-package verification within its recorded limits. The original rating was not revised.
